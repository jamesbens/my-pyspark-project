How to submit the python script to the master or worker:
we mention the path of the file, who is the master, and the file we want to execute
notice: by default, if we do not define a name to the master, the project name is concatenated to it.
docker exec -it pyspark2-spark-master-1 /opt/spark/bin/spark-submit --master spark://spark-master:7077 /opt/spark/work-dir/example1.py

Step1
Goto http://localhost:8080/
It shows the dockers are up and also which application (here example1.py) that is running or when it was completed.
We can also use the explain command that shows us the execution plan.

Step2
We need to provide additional commands for Docker to be able to connect to S3
So we provide the package org.apache.hadoop:hadoop-aws:3.5.0
This package is compatible with pyspark 4.2.0.
If we use a different pyspark version, we need to check which package is compatible.
Also we need ot provide the configuration spark.jars.ivy=/tmp/,.ivy2
Finaly we need to provide also the parameter that points to the .env file with credentials to access S3.
We add this in the docker-compose.yaml.
env_file: .env

for this to take affect execute command: docker compose down
then docker compose up -d (-d is to put the all process in the background)

example2.py
docker compose exec -it pyspark2-spark-master-1 /opt/spark/bin/spark-submit --master spark://spark-master:7077 --packages org.apache.hadoop:hadoop-aws:3.5.0  --conf spark.jars.ivy=/tmp/.ivy2
/opt/spark/work-dir/example2.py

Set the PYTHONPATH environment variable in your docker exec command so python3 can locate pyspark and its underlying py4j library:
docker exec -e PYTHONPATH=/opt/spark/python:/opt/spark/python/lib/py4j-0.10.9.9-src.zip pyspark2-spark-master-1 python3 -c "from pyspark.sql import SparkSession; spark = SparkSession.builder.config('spark.jars.packages', 'org.apache.hadoop:hadoop-aws:3.5.0').config('spark.jars.ivy', '/tmp/.ivy2').config('spark.hadoop.fs.s3a.aws.credentials.provider', 'org.apache.hadoop.fs.s3a.EnvironmentVariableCredentialsProvider').getOrCreate(); df = spark.read.text('s3a://my-pyspark-project-bckt/corpus.txt'); df.show(5)"

docker exec -it pyspark2-spark-master-1 /opt/spark/bin/spark-submit --master spark://spark-master:7077 --packages org.apache.hadoop:hadoop-aws:3.5.0  --conf spark.jars.ivy=/tmp/.ivy2 /opt/spark/work-dir/example3.py

To show how to verify inside the running Docker container that AWS environment variables are loaded correctly:
docker exec pyspark2-spark-master-1 printenv | findstr AWS

To test S3 connectivity directly using python inside the container shell:
Boto3 automatically reads AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY from the container's environment variables.
docker exec pyspark2-spark-master-1 python3 -c "import boto3; s3 = boto3.client('s3'); print(s3.list_objects_v2(Bucket='my-pyspark-project-bckt', MaxKeys=5))"
